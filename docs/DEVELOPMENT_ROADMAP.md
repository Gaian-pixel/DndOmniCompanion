## 1. Architectural Overview

D&D OmniCompanion is a Python Desktop Virtual Tabletop (VTT) and Campaign Management application structured cleanly around a Client-Server model:

```text
main.py (Single-Window Unified Launcher: DM Host | Player Client)
├── common/         # Shared GameState, Player model, TCP framing, TypedDict protocol, 5e tables, hex/square geometry, i18n, theme
├── server/         # DM GUI, Campaign Studio, Live Flow, Bestiary, Audio Library, VoiceServer (UDP 53912), TCP Server (TCP 5000)
│   └── rules/      # Decoupled 5e server-authoritative rule handlers dispatched via server/commands.py
├── client/         # Player Client GUI, Character Manager/Wizard/Sheet, Progression, PDF Sheet Generator, ClientNetwork, VoiceClient
├── components/     # Reusable Tkinter/ttkbootstrap widgets (HexMapCanvas, 3D Dice Canvas, StatblockCardView, Shop, Quests, Calendar)
├── campaigns/      # Campaign JSON & flow-graph projects (e.g., la_cripta_dei_sussurri)
├── manuals/        # Custom markdown rules + cached PDF index (pdf_index_cache.json)
├── scripts/        # Autonomous dev loop runner, roadmap parser & isolated quality gate (autonomous_dev_loop.py)
├── .agents/        # Antigravity workspace hooks (hooks.json, stop_quality_gate.py) & autonomous-loop skill
├── docs/           # Bilingual EN/IT User Guides, Operational Guides, Feature Maturity, UX Audit, Roadmap & Handoff
└── tests/          # 74 unittest modules (727 verified test cases, incl. GUI smoke/E2E & Phase 6 release readiness) + 2 multiplayer simulations
```

### Communication & Persistence Model
* **TCP Control & State (`common/network_utils.py`, `common/protocol.py`, `server/network.py`, `client/network.py`)**: Length-prefixed UTF-8 JSON framing over persistent TCP sockets (`send_message` using `select.select` write-readiness + parallel non-blocking `_dispatch_native_broadcast()` + `receive_message`). `Server.handle_client` dispatches requests via `server/commands.py:command_handlers`, after stripping test/debug override keys via `sanitize_client_payload`.
* **UDP Voice (`server/voice_server.py`, `client/voice_client.py`)**: Low-latency raw PCM audio relay on UDP port `53912`, guarded on Windows with `SIO_UDP_CONNRESET` and exponential backoff in `_play_loop`.
* **State & Thread Safety (`common/game_state.py`)**: Server-authoritative `GameState` protected by `threading.RLock()` (`game_state.lock`) and bridged to Tkinter via `gui_queue` + `safe_after`.
* **Persistence (`common/file_utils.py`)**: `atomic_save_json` (temp file in target directory + `.bak` backup + `os.replace`) and `load_json` (automatic `.bak` fallback recovery) used across `client_data/characters.json`, `client_data/settings.json`, `campaigns/*/campaign.json`, and `audio_library/library.json`.

## 3. Historical Critical Bugs & Technical Risks (All Resolved in `TASK-001`–`TASK-042`)

* All initial P1/P2 audit findings have been **resolved and verified by automated regression tests**:
  1. **Persistent Data Isolation (`TASK-001`, `TASK-041`)**: `DND_SETTINGS_PATH` and `DND_CHARACTERS_PATH` isolate all test runs; `.bak` crash recovery protects JSON persistence.

  3. **DM Privilege, Actor Ownership & Secrecy (`TASK-002`, `TASK-013`, `TASK-027`, `TASK-030`, `TASK-039`, `TASK-042`)**: Enforced `is_dm_actor`, `_resolve_actor`, FoW/tooltip/CommandPalette redaction, and non-DM `max_hp`/inspiration guards.
